# Daily News — 요구사항 명세서 (Specification)

## 1. Original Requirements
> 매일 아침 9시 각종 언론사에서 RSS를 통해 뉴스를 발췌해와서 정치,사회,경제,IT,글로벌 5개의 카테고리별로 뉴스레터를 만드는 프로그램

## 2. Overview
매일 오전 9시(KST)에 국내 언론사 RSS를 자동으로 수집한다. 정치·사회·경제·IT·글로벌 5개 카테고리별로 주요 기사를 골라 뉴스레터(Markdown 문서 + 정적 웹페이지)를 만든다. 결과물은 GitHub 저장소에 자동 커밋해서 일일 기록을 남기고, GitHub 잔디도 채운다.
Claude Pro 구독 외의 비용은 들지 않아야 한다. 그래서 실행할 때는 유료 AI API를 쓰지 않고, 규칙 기반으로 기사를 선정하고 요약한다.

## 3. Goals
- G1. 사람이 손대지 않아도 매일 1회 뉴스레터가 생성·게시된다.
- G2. 5개 카테고리마다 그날의 주요 기사 5건을 제공한다(하루 총 25건).
- G3. 각 기사에 원문 URL과, 원문 본문에만 근거한 짧은 요약을 함께 제공한다.
- G4. Markdown(저장소 아카이브)과 웹페이지(GitHub Pages) 두 형식으로 게시한다.
- G5. 매일 실행 결과가 기본 브랜치에 커밋되어 GitHub 기여 그래프(잔디)에 반영된다.
- G6. 운영 비용 0원(무료 인프라와 무료 라이브러리만 사용)

## 4. User Stories
- US1. 나는 독자로서 아침에 웹페이지 하나만 열면 5개 분야 핵심 뉴스를 5분 안에 훑어보고 싶다.
- US2. 나는 독자로서 기사마다 2~3문장 요약과 원문 URL을 보고, 더 궁금하면 원문으로 바로 이동하고 싶다.
- US3. 나는 독자로서 여러 언론사가 함께 다룬 사안인지 알고 싶다. 그래야 중요도를 판단할 수 있다.
- US4. 나는 독자로서 지난 뉴스레터를 날짜별로 다시 찾아보고 싶다. 최근 30일 것은 웹페이지에서, 그 이전 것은 저장소의 Markdown 아카이브에서 본다.
- US5. 나는 운영자로서 PC를 꺼 둬도 매일 자동으로 실행되길 원한다.
- US6. 나는 운영자로서 특정 언론사 RSS가 실패해도 나머지로 뉴스레터가 만들어지길 원한다.
- US7. 나는 운영자로서 필요할 때 수동으로 즉시 실행해서 결과를 확인하고 싶다.
- US8. 나는 운영자로서 언론사나 피드 URL을 코드 로직 수정 없이 설정만 바꿔서 추가·삭제하고 싶다.

## 5. Functional Requirements

### FR-1 스케줄 실행
- FR-1.1 매일 **09:00 KST**(= 00:00 UTC, cron `0 0 * * *`)에 자동 실행되도록 예약한다.
- FR-1.2 수동 실행 트리거를 제공한다.
- FR-1.3 날짜는 KST 기준으로 계산한다.

### FR-2 RSS 수집
- FR-2.1 기본 언론사·카테고리 피드는 아래와 같다(2026-10-28 동작 확인).

| 카테고리 | 연합뉴스 | 동아일보 | 경향신문 |
|---|---|---|---|
| 정치 | yna.co.kr/rss/politics.xml | rss.donga.com/politics.xml | khan.co.kr/rss/rssdata/politic_news.xml |
| 사회 | yna.co.kr/rss/society.xml | rss.donga.com/national.xml | khan.co.kr/rss/rssdata/society_news.xml |
| 경제 | yna.co.kr/rss/economy.xml | rss.donga.com/economy.xml | khan.co.kr/rss/rssdata/economy_news.xml |
| IT | yna.co.kr/rss/industry.xml (IT 키워드 필터) | rss.donga.com/science.xml | khan.co.kr/rss/rssdata/science_news.xml |
| 글로벌 | yna.co.kr/rss/international.xml | rss.donga.com/international.xml | khan.co.kr/rss/rssdata/kh_world.xml |

- FR-2.2 RSS 2.0의 날짜 형식(`pubDate`, `dc:date`, CDATA로 감싼 날짜)을 모두 파싱한다.
- FR-2.3 실행 시각 기준 최근 24시간 안에 발행된 기사만 대상으로 한다.
- FR-2.4 피드 URL·언론사·카테고리 매핑은 설정(코드 내 단일 설정 위치 또는 설정 파일)으로 관리한다.
- FR-2.5 피드 요청이 실패하거나 시간 초과되면 해당 피드만 건너뛰고 로그에 남긴다.

### FR-3 정제 및 중복 제거
- FR-3.1 링크의 추적 파라미터(`utm_*` 등)를 제거해서 정규화한다.
- FR-3.2 같은 링크, 또는 정규화한 제목이 같은 기사는 하나로 합친다.
- FR-3.3 연합뉴스 산업 피드는 IT 키워드 목록에 맞는 기사만 IT 카테고리에 넣는다.

### FR-4 주요 기사 선정 (AI 미사용)
- FR-4.1 제목 유사도로 같은 사안을 다룬 기사들을 하나의 "사안(Story)"으로 묶는다.
- FR-4.2 사안 점수 = 보도 언론사 수(주요 가중치) + 최신성(보조 가중치)
- FR-4.3 카테고리별 상위 5개 사안을 고른다. 각 사안에는 대표 기사 1건과 같은 사안을 다룬 다른 언론사의 원문 URL을 둔다.
- FR-4.4 후보가 5개보다 적으면 있는 만큼만 표시한다.

### FR-5 요약 (본문 기반, AI 미사용)
- FR-5.1 대표 기사의 원문 페이지에서 본문을 추출한다. 본문 위치(selector)는 언론사별로 설정한다.
- FR-5.2 크레디트(`(서울=연합뉴스) ○○○ 기자 =`), 기자 이메일, 사진 설명, 광고, 관련기사 문구를 제거한다.
- FR-5.3 본문 첫 2~3문장(최대 약 200자)을 요약으로 쓴다(리드 추출).
- FR-5.4 본문 추출에 실패하면 RSS 설명문을 정제해서 대신 쓴다. 이것도 없으면 요약 없이 제목과 링크만 표시한다.
- FR-5.5 요약에는 원문에 없는 문장을 생성·추가하지 않는다.

### FR-6 오늘의 키워드
- FR-6.1 수집한 전체 기사 제목에서 명사 빈도 상위 10개를 키워드로 뽑는다. 불용어는 제외한다.

### FR-7 출력
- FR-7.0 모든 기사 항목에는 **원문 URL**(정규화된 전체 주소)을 반드시 포함한다. 제목 하이퍼링크와 별도로 URL 문자열도 표시한다.
- FR-7.1 Markdown: `news/YYYY/MM/YYYY-MM-DD.md`. 포함 항목은 헤더(날짜, 수집 언론사, 수집·선정 건수), 오늘의 키워드, 카테고리별 기사(제목, 원문 URL, 언론사, 발행 시각, 보도 언론사 수, 요약, 같은 사안의 다른 언론사 원문 URL)다.
- FR-7.2 웹페이지:
  - `site/index.html`(오늘), `site/archive/YYYY-MM-DD.html`(날짜별), `site/archive.html`(목록). `docs/`는 SDD 문서용이라 웹 출력과 분리한다
  - 카테고리 탭, 기사 카드, 키워드 칩, 언론사 배지를 둔다
- FR-7.3 `README.md`에 최신 뉴스레터 링크와 웹페이지 주소를 갱신한다.
- FR-7.4 같은 날짜에 다시 실행하면 그날 파일을 덮어쓴다(멱등).
- FR-7.5 보관 정책
  - 웹 날짜별 페이지(`site/archive/YYYY-MM-DD.html`)는 실행 날짜 포함 **최근 30일**만 보관하고, 그보다 오래된 파일은 실행할 때 삭제한다. `site/archive.html` 목록도 남은 파일 기준으로 다시 만든다.
  - Markdown 아카이브(`news/`)는 **삭제하지 않고 영구 보관**한다.
  - 보관 기간은 설정값이다(웹 30일, Markdown 무기한). 코드 수정 없이 바꿀 수 있다.
  - 삭제 대상은 `YYYY-MM-DD.html` 이름 패턴의 파일로만 한정한다. 다른 파일은 건드리지 않는다.

### FR-8 게시
- FR-8.0 브랜치 규칙: 개발 작업은 작업 브랜치(예: `feature/daily-news`)에서 하고, main에는 Pull Request 병합으로만 반영한다.
- FR-8.1 생성된 뉴스레터 파일은 **main에 직접 커밋·푸시**한다. 일일 뉴스 커밋만 main 보호 규칙의 예외(배포 키 bypass)로 허용한다(`/sdd:plan`에서 확정).
- FR-8.2 커밋 작성자 이메일은 저장소 소유자의 GitHub 계정 이메일로 설정한다(잔디 반영 조건).
- FR-8.3 변경 사항이 없으면 커밋을 건너뛴다.
- FR-8.4 웹페이지는 GitHub Pages로 공개한다. 배포 소스는 GitHub Actions이고, main의 `site/` 폴더를 배포한다.

## 6. Non-Functional Requirements
- NFR-1 성능: 1회 전체 실행(수집부터 게시까지)이 5분 안에 끝난다. 원문 요청은 기사 최대 25건(+재시도)으로 제한한다.
- NFR-2 신뢰성: 언론사 1곳 이상이 실패해도 뉴스레터가 생성된다. 모든 피드가 실패하면 실행을 실패로 처리하고 커밋하지 않는다.
- NFR-3 예의 있는 수집:
  - 요청마다 User-Agent를 명시하고, 같은 호스트에는 순차로 요청하며 짧은 지연을 둔다.
  - 각 사이트 robots.txt가 허용하는 경로만 요청한다.
  - 하루 1회 실행이다.
- NFR-4 저작권: 기사 본문 전체는 저장하지 않는다. 제목, 링크, 짧은 리드 인용(최대 약 200자)만 저장하고 출처를 항상 표시한다.
- NFR-5 보안: API 키는 쓰지 않는다. 비밀값은 main 직접 push용 배포 키 1개뿐이고 GitHub Secrets에 저장한다. 저장소에 자격 증명을 커밋하지 않는다. 워크플로 권한은 job별 최소 권한으로 둔다.
- NFR-6 접근성: 웹페이지는 시맨틱 HTML을 쓰고, 키보드로 탭을 이동할 수 있다. 색 대비는 WCAG AA를 지키고, 다크모드와 모바일(360px 폭) 화면을 지원한다.
- NFR-7 유지보수성: 수집·선정·요약·출력 단계를 분리한다. 파서·추출기는 저장해 둔 샘플 RSS/HTML로 단위 테스트할 수 있다.
- NFR-8 관찰성: 실행 로그에 피드별 수집 건수, 실패 피드, 선정 결과, 본문 추출 성공률을 남긴다.

## 7. Constraints & Assumptions
### Constraints
- C1. 언어는 Java다.
- C2. 비용 0원. Claude Pro 구독 외의 유료 서비스·API는 쓰지 않는다. Claude는 개발할 때만 쓴다.
- C3. 저장소와 실행 환경은 GitHub(public 저장소, GitHub Actions 무료 사용)다.
- C4. 뉴스 소스는 RSS만 쓴다. 공식 RSS가 없는 언론사(중앙일보, KBS, 채널A)와, robots.txt가 RSS 경로(`/xml/`)를 막는 서울신문은 제외한다.
- C5. 카테고리는 정치, 사회, 경제, IT, 글로벌로 고정한다. 카테고리당 최대 5건이다.

### Assumptions
- A1. 확인된 RSS URL과 기사 본문 HTML 구조는 당분간 유지된다. 바뀌면 설정·selector 수정으로 대응한다.
- A2. 예약 시각은 09:00 KST 정각이다. GitHub Actions 스케줄은 정각 혼잡 때문에 수 분에서 수십 분 늦게 시작될 수 있다. 이 지연은 허용한다(SC1 기준 10:00).
- A3. 저장소는 매일 커밋되므로, 비활성 저장소의 스케줄이 자동 중지되는 조건(60일)에 걸리지 않는다.
- A4. "글로벌" 카테고리는 각 언론사의 국제(세계) 섹션 피드로 정의한다.
- A5. 대상 언론사는 연합뉴스·동아일보·경향신문 3곳이다. 서울신문은 robots.txt 정책이 바뀌면 설정만 추가해 다시 넣을 수 있다.

## 8. Success Criteria
- SC1. 연속 7일 동안 매일 10:00 KST 이전에 `news/` 파일과 `site/index.html`이 자동 커밋된다(수동 개입 0회).
- SC2. 7일 동안 GitHub 프로필 잔디가 매일 채워진다.
- SC3. 매일 카테고리 5개가 모두 존재하고, 각 카테고리에 기사가 5건(후보가 부족한 날 제외) 있다.
- SC3-1. 게시된 모든 기사 항목(100%)에 원문 URL이 있고, 해당 URL이 HTTP 200으로 열린다.
- SC4. 선정 기사 중 90% 이상이 원문 본문 기반 요약을 가진다(RSS 설명 대체나 요약 없음은 10% 이하).
- SC5. 요약 문장은 모두 원문 본문(또는 RSS 설명)에 그대로 들어 있는 문장이다. 테스트로 검증한다.
- SC6. 언론사 1곳의 피드 URL을 일부러 고장 낸 테스트 실행에서도 뉴스레터가 생성된다.
- SC7. 웹페이지가 모바일 폭 360px에서 가로 스크롤 없이 표시되고, 라이트·다크 모드 모두에서 읽힌다.
- SC8. 운영 비용 청구 0원(GitHub Actions 무료 한도 안, 유료 API 호출 0회)
- SC9. 31일째 실행 후 `site/archive/`에는 최근 30일치 파일만 남고, `news/`의 Markdown은 첫날 것부터 모두 남아 있다.
