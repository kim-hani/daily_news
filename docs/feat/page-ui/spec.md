# 뉴스레터 웹 페이지 UI 개선 명세 (feat/page-ui)

## 1. Original Requirements

> 뉴스레터 웹 페이지(site/) UI 개선 — magic MCP와 21st.dev 컴포넌트를 활용해 디자인 적용
> 꾸밀 화면: 홈 화면/홈 화면에서 오늘의 뉴스피드로 넘어갈 수 있는 버튼/홈 화면에서 캘린더 형식으로 보여지는 뉴스피드로 넘어갈 수 있는 버튼/오늘의 뉴스피드 페이지/캘린더 형식의 뉴스피드 페이지
> 원하는 분위기: 깔끔하고 센세이셔널한 분위기
> 반응형(모바일) 지원
> 직관적이고 트렌디한 UI

(이전 요청) "magic mcp 와 21st.dev를 사용하여 뉴스레터 웹 페이지 ui를 꾸미고 싶어. 일단 내가 먼저 찾아볼건데 디자인 못찾겠으면 너에게도 부탁할게"

(UI 확정 지시, 2026-11-02)

> 일단 전체 테마를 흰색배경으로 진행하자
> 1.홈 화면의 히어로의 Text는 큰 텍스트 2줄만 사용한다.
> 2.Text 내용 : EveryDay. \n News Feed
> 3.주 버튼의 버튼으로 텍스트 밑에 2개의 버튼을 만든다.
> 4. 버튼의 내용은 Today 와 Callendar
> 5.Today는 오늘의 뉴스피드로 넘어감 / Callendar버튼을 누르면 캘린더로 넘어감
> 6. 캘린더에서 해당 날짜를 누르면 해당 날짜의 뉴스 피드로 넘어감
> 나머지는 그냥 내가 고른 스타일대로 필요한곳에 들어가면 될거같아

확인 질문으로 정한 항목:

| 항목 | 결정 |
|---|---|
| 다크모드 | 배경을 고르는 옵션(**White / Dark / System**)을 만든다. 기본값은 System이다(처음 방문하면 기기 설정을 따른다. 2026-11-02 White에서 변경). 라이트일 때 배경은 흰색이다. 전환 버튼도 21st.dev 컴포넌트를 쓴다. |
| 홈 구성 | 히어로 두 줄과 버튼 2개만 두는 **미니멀 홈**이다. 키워드와 통계는 뉴스피드로 옮긴다. |
| 버튼 철자 | `Callendar`가 아니라 `Calendar`로 표기한다. |
| 날짜 표시 | 버튼 아래에 최신 뉴스레터 날짜를 작게 보여 준다(예: `Latest · 2026-11-02 (월)`). |

사용자가 고른 21st.dev 컴포넌트는 FR-5.1 표에 정리했다.

## 2. Overview

지금 `site/`는 Java 파이프라인이 Thymeleaf 템플릿으로 매일 생성하는 정적 페이지 세 종류로 되어 있다.

| 현재 파일 | 내용 |
|---|---|
| `site/index.html` | 오늘 뉴스레터(카테고리 탭 + 기사 카드) |
| `site/archive/YYYY-MM-DD.html` | 날짜별 뉴스레터(최근 30일 보관), `index.html`과 같은 템플릿 |
| `site/archive.html` | 연·월별 날짜 링크 목록 |

이번 작업은 수집·선정·요약 로직은 그대로 두고 **웹 화면 구성과 디자인만 바꾼다**. 화면은 다음 세 가지로 다시 짠다.

1. **홈 화면**(새로 추가): 큰 두 줄 히어로(`EveryDay.` / `News Feed`)와 `Today`, `Calendar` 두 버튼만 둔 미니멀한 첫 화면이다.
2. **오늘의 뉴스피드**: 지금의 뉴스레터 페이지를 새 디자인으로 바꾼다. 오늘의 키워드와 통계도 이 화면에서 보여 준다. 날짜별 페이지도 같은 디자인을 쓴다.
3. **캘린더 뉴스피드**: 지금의 날짜 목록을 월 달력 화면으로 바꾼다. 날짜를 누르면 그날 뉴스피드로 간다.

디자인은 사용자가 고른 21st.dev 컴포넌트 9개(FR-5.1)를 바탕으로 한다. 라이트 배경은 **흰색**이다. 처음 방문하면 기기 설정(라이트/다크)을 따르고, 방문자가 White / Dark / System 중에서 배경을 고를 수 있다(FR-7). 목표 분위기는 **깔끔하고 센세이셔널하며, 직관적이고 트렌디한** UI다.

## 3. Goals

- G1. 홈 → 오늘의 뉴스피드, 홈 → 캘린더 뉴스피드로 각각 **한 번 클릭/탭**에 이동할 수 있다.
- G2. 21st.dev 컴포넌트로 세 화면의 디자인을 통일한다. 디자인 방향은 "깔끔함(여백·정돈된 타이포)과 센세이셔널함(강한 헤드라인 타이포·강조색·절제된 모션)"이다.
- G3. 날짜별 뉴스레터를 달력에서 직관적으로 찾아 들어갈 수 있다.
- G4. 360px 모바일부터 데스크톱까지 같은 기능을 쓸 수 있다.
- G5. 지금 보장하던 사항(원문 링크, 저작권 고지, 접근성, 다크모드, 매일 자동 생성·배포)은 하나도 잃지 않는다. 다크모드는 시스템 설정을 자동으로 따르던 방식에서 **방문자가 고르는 방식**(White / Dark / System, 기본 System)으로 바뀐다.

## 4. User Stories

- US-1. 방문자로서 사이트 주소(`https://kim-hani.github.io/daily_news/`)에 들어가면 군더더기 없는 첫 화면에서 서비스 이름과 최신 뉴스 날짜를 보고, 바로 오늘 뉴스나 캘린더로 가고 싶다.
- US-2. 방문자로서 홈에서 눈에 잘 띄는 `Today` 버튼을 눌러 오늘 기사로 바로 가고 싶다.
- US-3. 방문자로서 홈에서 `Calendar` 버튼을 눌러 지난 날짜의 뉴스를 달력에서 고르고 싶다.
- US-4. 독자로서 오늘의 뉴스피드 상단에서 오늘의 키워드와 통계를 보고, 카테고리(정치·사회·경제·IT·글로벌)를 빠르게 바꿔 가며 기사 카드를 훑고, 관심 있는 기사는 원문으로 가고 싶다.
- US-5. 독자로서 달력에서 뉴스레터가 있는 날과 없는 날을 바로 구분하고, 있는 날을 누르면 그날 뉴스피드로 가고 싶다.
- US-6. 모바일 사용자로서 한 손으로 스크롤하고 탭해도 버튼·탭·날짜 칸을 정확히 누를 수 있으면 좋겠다.
- US-7. 키보드·스크린리더 사용자로서 새 화면에서도 모든 버튼·탭·날짜에 접근하고 내용을 읽을 수 있어야 한다.
- US-8. 운영자로서 디자인을 바꾼 뒤에도 매일 GitHub Actions 실행만으로 새 화면이 생성·배포되기를 바란다. 손으로 고칠 일은 없어야 한다.
- US-9. 방문자로서 배경을 White, Dark, System 중에서 골라 두면 다른 페이지로 가거나 다시 방문해도 그 배경이 유지되면 좋겠다.

## 5. Functional Requirements

우선순위: **Must**(필수) / **Should**(가능하면) / **Could**(여유 있으면)

### FR-1 페이지 구성과 이동

- FR-1.1 (Must) 사이트에는 **홈**, **오늘의 뉴스피드**, **캘린더 뉴스피드**, **날짜별 뉴스피드** 페이지가 있다. 실제 파일명과 경로는 plan에서 정한다.
- FR-1.2 (Must) 사이트 루트(`/`, `index.html`)로 들어오면 **홈**이 보인다.
- FR-1.3 (Must) 기존 URL이 깨지지 않는다. `/archive.html`과 `/archive/YYYY-MM-DD.html`(보관 기간 안)은 계속 열리며, 같은 내용 페이지를 보여 주거나 그 페이지로 리다이렉트한다.
- FR-1.4 (Must) 모든 페이지 상단에 공통 내비게이션(브랜드 로고/이름 → 홈, Today, Calendar, 배경 전환 버튼)이 있다. 지금 보고 있는 페이지는 시각적으로 표시하고 `aria-current="page"`도 붙인다.
- FR-1.5 (Must) 모든 페이지 하단에 지금 푸터 내용(인용·저작권 고지, 생성 시각, GitHub 저장소 링크)을 그대로 둔다.

### FR-2 홈 화면

홈은 **미니멀**하게 만든다. 공통 내비게이션과 푸터 사이에는 아래 요소만 둔다.

- FR-2.1 (Must) 히어로 텍스트는 **큰 텍스트 두 줄만** 쓴다. 1줄은 `EveryDay.`, 2줄은 `News Feed`다. 이 제목이 페이지의 `<h1>`이다. 한 줄 소개, 부제, 장식 문구는 두지 않는다.
- FR-2.2 (Must) 히어로 텍스트 바로 아래에 **버튼 2개**를 둔다. 둘 다 같은 버튼 컴포넌트(FR-5.1의 `flow-button`)를 쓴다.
  - `Today`: 누르면 오늘의 뉴스피드(최신 뉴스레터)로 간다. 첫 번째 버튼이고, 둘 중 더 눈에 띈다.
  - `Calendar`: 누르면 캘린더 뉴스피드로 간다.
- FR-2.3 (Must) 버튼 아래에 최신 뉴스레터 날짜를 작은 글씨로 보여 준다. 예: `Latest · 2026-11-02 (월)`. 낮 12시 생성 전에 들어온 방문자가 `Today`가 전날 뉴스라는 것을 알 수 있게 하기 위해서다(A1).
- FR-2.4 (Must) 히어로 텍스트와 두 버튼은 360px 폭에서 스크롤하지 않아도 첫 화면 안에 보인다(뷰포트 360×640 기준).
- FR-2.5 (Must) 오늘의 키워드, 통계, 카테고리별 헤드라인은 홈에 두지 않는다. 키워드와 통계는 뉴스피드 상단에서 보여 준다(FR-3.9).

### FR-3 오늘의 뉴스피드 (및 날짜별 뉴스피드)

- FR-3.1 (Must) 최신 뉴스레터 한 건을 보여 준다. 날짜별 뉴스피드는 같은 레이아웃으로 해당 날짜 뉴스레터를 보여 준다.
- FR-3.2 (Must) 지금 페이지에 있는 정보를 **모두** 유지한다: 날짜, 통계 한 줄, 수집 실패 피드 안내, 오늘의 키워드, 카테고리 5개, 기사별 제목·언론사·시각·"N개 언론사 보도"·요약 인용·"RSS 요약" 표시·원문 URL·같은 사안 링크, 기사가 없는 카테고리 안내 문구.
- FR-3.3 (Must) 카테고리 전환 UI(탭, 세그먼트 컨트롤 등)를 둔다. JS가 동작하면 탭처럼 전환된다. JS가 없으면 모든 섹션이 보이고 탭은 섹션 앵커로 동작한다(지금 동작 유지). URL 해시(`#politics` 등)로 특정 카테고리를 바로 열 수 있다.
- FR-3.4 (Must) 기사 카드는 제목을 가장 크게 보여 주고, 메타 정보(언론사·시각·보도 수)는 배지 형태로 구분해 훑어보기 쉽게 한다.
- FR-3.5 (Must) 모든 기사에 원문 URL 링크가 있다. 지금 테스트(FR-7.0, SC3-1) 조건을 그대로 지킨다.
- FR-3.6 (Should) 날짜별 뉴스피드에는 "이전 날짜 / 다음 날짜" 이동 링크와 "캘린더로 돌아가기" 링크가 있다. 보관 기간 밖의 날짜로는 링크하지 않는다.
- FR-3.7 (Should) 모바일에서 아래로 스크롤해도 카테고리 전환 UI가 상단에 고정(sticky)된다.
- FR-3.8 (Could) 카드가 화면에 들어올 때 짧은 등장 애니메이션을 준다(NFR-5 준수).
- FR-3.9 (Must) 뉴스피드 상단(카테고리 전환 UI 위)에 **오늘의 키워드**(최대 10개)와 **통계 숫자**(수집 → 중복 제거 → 선정)를 보여 준다. 키워드는 배지(`base-badge`)로 보여 준다. 통계는 숫자를 크게 강조하고, 화면에 들어올 때 0부터 세어 올라가는 효과(`counting-number`)를 준다. 최종 숫자는 처음부터 HTML 안에 있다(NFR-7).

### FR-4 캘린더 뉴스피드

- FR-4.1 (Must) 월 단위 달력(일요일 시작, 7열)을 보여 준다. 처음 열면 최신 뉴스레터가 있는 달이 나온다.
- FR-4.2 (Must) 웹 페이지가 있는 날짜(`site/archive/YYYY-MM-DD.html`이 있는 날)는 **활성 칸**이다. 누르면 그날 뉴스피드로 간다. 없는 날은 비활성으로 표시하고 누를 수 없다.
- FR-4.3 (Must) 최신 뉴스레터 날짜(오늘)는 다른 활성 칸과 구분되게 강조한다.
- FR-4.4 (Must) 보관 기간(최근 30일)이 두 달에 걸치면 이전/다음 달로 이동할 수 있다. 보관 데이터가 없는 달로는 이동할 수 없다(버튼 비활성).
- FR-4.5 (Must) 지금 안내 문구(웹은 최근 30일 보관, 그 이전은 저장소 Markdown 아카이브 링크)를 유지한다.
- FR-4.6 (Must) JS 없이도 보관된 모든 날짜로 갈 수 있다. 예: 정적 HTML 달력, 또는 달력 아래 날짜 목록 대체 표시.
- FR-4.7 (Should) 활성 날짜 칸에 그날의 짧은 정보(대표 키워드 1개 또는 선정 기사 수)를 보여 준다. 모바일처럼 칸이 좁으면 점(dot) 표시로 줄여도 된다.
- FR-4.8 (Could) 날짜 칸에 마우스를 올리거나 포커스하면 그날 키워드 상위 3개를 미리 보여 준다(툴팁/팝오버).
- FR-4.9 (Must) 보관된 뉴스레터가 하나도 없으면 "아직 보관된 뉴스레터가 없습니다" 안내를 보여 준다.

- FR-5.1 (Must) 주요 UI 요소는 사용자가 고른 아래 21st.dev 컴포넌트를 바탕으로 만든다(2026-11-02 확정). 표에 없는 요소(푸터, 날짜 이동 링크, 빈 상태 안내 등)는 이 컴포넌트들의 스타일과 토큰을 따라 만든다.

  | 기사 카드 + 메타 배지 | 뉴스피드 | `spotlight-card` | https://21st.dev/@preetsuthar17/components/spotlight-card |
  | 월 달력 | 캘린더 | `new-calendar` | https://21st.dev/@edwinvakayil/components/new-calendar |

- FR-5.2 (Must) 컴포넌트는 사용자가 고른다. 위 표의 컴포넌트를 바꾸거나 요소를 더할 때도 사용자가 먼저 고르고, 사용자가 요청하면 magic MCP(`search`, `get_inspiration` 등)로 후보를 찾아 제시한 뒤 사용자가 확정한다.
- FR-5.3 (Must) 쓴 컴포넌트마다 출처(21st.dev URL 또는 컴포넌트 ID), 라이선스, 원본에서 바꾼 점을 문서(`docs/feat/page-ui/` 아래)에 기록한다.
- FR-5.4 (Must) 색, 타이포그래피, 간격, 모서리 반경, 그림자는 디자인 토큰(CSS 변수 등) 하나로 관리한다. 세 화면 모두 같은 토큰을 쓴다.

### FR-6 생성 파이프라인 연동

- FR-6.1 (Must) 새 화면은 모두 지금처럼 `./gradlew run` 한 번으로 생성된다. 사람이 HTML을 손으로 고치는 단계는 없다.
- FR-6.2 (Must) 홈과 캘린더에 필요한 데이터(최신 날짜, 키워드, 통계, 보관 날짜 목록 등)는 파이프라인이 이미 만드는 데이터에서 얻는다. 수집·선정·요약 로직은 바꾸지 않는다.
- FR-6.3 (Must) 30일 보관 정리(RetentionCleaner)가 끝난 뒤에는 캘린더에 남아 있는 날짜만 활성으로 나온다(지금 archive 목록과 같은 순서 보장).
- FR-6.4 (Must) 날짜별 페이지와 HTML 페이지에서 쓰는 CSS·JS 같은 정적 자원은 `site/` 안에 있다. 그래서 GitHub Pages 배포 결과만으로 동작한다.

### FR-7 배경(테마) 선택

- FR-7.1 (Must) 방문자는 배경을 **White**, **Dark**, **System** 중에서 고를 수 있다. System은 기기의 `prefers-color-scheme` 설정을 따른다.
- FR-7.2 (Must) 처음 방문하면(저장된 선택이 없으면) **System**이다. 기기가 라이트모드면 흰색, 다크모드면 어두운 배경으로 보인다. 배경 전환 버튼에도 System이 선택된 상태로 표시된다.
- FR-7.3 (Must) 배경 전환 버튼(`theme-switcher-1`)은 모든 페이지의 상단 내비게이션에 있다. 세 선택지는 각각 키보드로 고를 수 있고, 지금 고른 값을 스크린리더가 읽을 수 있다(예: 라디오 그룹, `aria-checked`).
- FR-7.4 (Must) 고른 값은 브라우저에 저장된다. 다른 페이지로 가거나 다시 방문해도 유지된다.
- FR-7.5 (Must) 페이지를 열 때 고른 배경과 다른 배경이 잠깐 보였다가 바뀌는 깜빡임이 없다. 예: 다크 기기에서 White를 고른 경우, 라이트 기기에서 Dark를 고른 경우.
- FR-7.6 (Must) System을 고른 상태에서 방문 중에 기기 설정이 바뀌면 새로고침 없이 배경이 따라 바뀐다.
- FR-7.7 (Must) JS가 꺼져 있거나 로드에 실패해도 기기 설정을 따른다(CSS만으로 동작). 이때 배경 전환 버튼은 숨긴다.
- FR-7.8 (Must) 전환 기간에 남아 있는 옛 디자인의 날짜별 페이지(§7 A6)는 이 기능을 지원하지 않아도 된다.

## 6. Non-Functional Requirements

- NFR-1 반응형: 360px, 768px, 1280px 폭에서 가로 스크롤이 없다. 레이아웃은 모바일 우선으로 짠다. 달력은 360px에서도 7열이 유지된다.
- NFR-2 터치 대상: 버튼, 탭, 달력 날짜 칸 등 누를 수 있는 요소는 최소 44×44px(CSS px)이다.
- NFR-3 접근성: WCAG 2.1 AA를 지킨다. 시맨틱 HTML, 본문·UI 색 대비 4.5:1(큰 글씨 3:1) 이상, 모든 상호작용 요소의 키보드 접근과 보이는 포커스 표시, 달력 날짜 칸의 접근 가능한 이름(예: "2026년 10월 31일 토요일, 뉴스레터 있음"), 탭의 ARIA 패턴(지금 tabs.js 동작 유지)이 필요하다. Lighthouse Accessibility 점수는 세 화면 모두 **95점 이상**이어야 한다.
- NFR-4 테마: 라이트 배경은 흰색(White)이다. 처음에는 기기 설정을 따르고(System), FR-7에 따라 White와 Dark를 직접 고를 수 있다. White와 Dark 두 모드 모두 NFR-3의 대비 기준을 지킨다. 고른 21st.dev 컴포넌트 9개는 모두 두 모드의 색을 갖는다.
- NFR-5 모션: 애니메이션은 상태 전달이나 강조에만 쓴다. 길이는 400ms 이하다. 단, 통계 숫자 카운트업(FR-3.9)은 1초 이하로 한 번만 실행한다. `prefers-reduced-motion: reduce`이면 장식 애니메이션(히어로 글자 굵기 변화, 버튼 흐름 효과, 카드 스포트라이트, 카운트업, 등장 효과)을 끄고 최종 상태를 바로 보여 준다. 자동 재생 모션에는 일시정지 수단이 있거나, 5초 이내에 멈춘다.
- NFR-6 성능: Lighthouse 모바일 기준 Performance **90점 이상**, LCP 2.5초 이하, CLS 0.1 이하를 지킨다. 첫 로드의 CSS+JS 전송량(gzip)은 페이지당 **150KB 이하**다.
- NFR-7 점진적 향상: 기사 제목, 요약, 원문 링크, 날짜 링크 같은 핵심 콘텐츠는 생성된 HTML 안에 있다. JS가 꺼져 있거나 로드에 실패해도 모든 콘텐츠를 읽고 이동할 수 있다.
- NFR-8 보안: 기사 제목과 요약은 지금처럼 HTML 이스케이프해서 출력한다(`<script>` 제목 → 텍스트). 외부 스크립트를 쓰면 출처를 최소화하고 문서에 기록한다. 인라인 이벤트 핸들러는 쓰지 않는다.
- NFR-9 브라우저 지원: 최신 2개 버전의 Chrome, Edge, Safari(iOS 포함), Firefox, 그리고 Samsung Internet을 지원한다.
- NFR-10 유지보수성: 디자인 토큰과 컴포넌트 스타일은 한곳에 모은다. 템플릿은 화면별로 나누되 공통 조각(헤더·푸터·head)은 재사용한다.
- NFR-11 한글 타이포: `word-break: keep-all`처럼 한글 줄바꿈 품질을 유지한다. 웹폰트를 쓰면 `font-display: swap`과 시스템 폰트 대체를 지정한다.

## 7. Constraints & Assumptions

### 제약
- C1. 호스팅은 GitHub Pages(정적 파일)다. 서버 측 실행과 API는 없다.
- C2. HTML은 지금 Java 파이프라인(Thymeleaf standalone)이 매일 GitHub Actions에서 생성한다. 운영 비용은 0원을 유지한다.
- C3. 21st.dev 컴포넌트는 대부분 React + Tailwind CSS 기반이다. 지금 정적 템플릿 구조에 맞게 옮길지(정적 HTML/CSS/바닐라 JS로 이식, Tailwind 빌드 추가 등), 프런트엔드 빌드를 새로 들일지는 **plan 단계에서 정한다**. 어느 방식이든 NFR-6, NFR-7과 FR-6.1을 지켜야 한다.
- C4. 수집·선정·요약 로직과 Markdown(`news/`), README 출력 형식은 바꾸지 않는다.
- C5. 기사 썸네일 등 언론사 이미지는 저작권 문제로 쓰지 않는다. 시각적 강조는 타이포그래피, 색, 아이콘, 일러스트로 한다.

### 가정
- A1. "오늘의 뉴스피드"는 **가장 최근에 생성된 뉴스레터**를 뜻한다. 낮 12시 실행 전에 들어오면 전날 뉴스레터가 보이며, 날짜 표기로 이를 알 수 있다.
- A2. 캘린더의 활성 날짜는 웹 보관 기간(최근 30일) 안에 페이지가 있는 날로 한정한다. 30일보다 오래된 날은 지금처럼 저장소 Markdown 아카이브 링크로 안내한다.
- A3. 사용할 21st.dev 컴포넌트는 사용자가 먼저 고른다. 정해지지 않은 요소는 magic MCP 검색으로 후보를 제시하고 확정받는다. 컴포넌트를 확정하기 전에도 레이아웃과 데이터 연동 작업은 할 수 있다.
- A4. 사용자 계정, 검색, 구독(이메일), 댓글 기능은 이번 범위에 넣지 않는다.
- A5. 배경 선택값은 방문자 브라우저의 `localStorage`에만 저장한다. 쿠키나 서버 저장은 쓰지 않는다.
- A6. 배포 시점에 이미 있는 날짜별 페이지는 옛 디자인 그대로 남았다가 30일 보관 정리로 사라진다. 이 페이지들은 새 디자인과 배경 선택을 적용하지 않는다.
- A7. 히어로 텍스트(`EveryDay.` / `News Feed`)와 버튼 글자(`Today` / `Calendar`)는 영어다. 그 밖의 안내 문구와 기사 내용은 지금처럼 한국어다.

### 범위 밖
- 뉴스 검색, 카테고리별 필터가 있는 캘린더, 이메일 구독, PWA/오프라인, 다국어.

## 8. Success Criteria

- SC1. 홈(`/`)에서 `Today` 버튼 1회 클릭으로 최신 뉴스레터 페이지가 열리고, `Calendar` 버튼 1회 클릭으로 캘린더 페이지가 열린다. 히어로 두 줄과 두 버튼은 360×640 뷰포트의 첫 화면에 보인다.
- SC2. 캘린더에서 보관된 모든 날짜가 활성으로 표시되고, 각각 누르면 해당 날짜 뉴스피드가 열린다(404 0건). 보관되지 않은 날짜는 누를 수 없다.
- SC3. 기존 URL `/`, `/archive.html`, `/archive/YYYY-MM-DD.html`(보관 기간 안)에 들어가도 404가 0건이다.
- SC4. 뉴스피드 페이지에서 FR-3.2의 모든 정보 항목이 렌더링되고, 모든 기사에 원문 URL이 있다(자동 테스트로 검증).
- SC5. 360px, 768px, 1280px 폭에서 세 화면 모두 가로 스크롤이 없다.
- SC6. 세 화면 모두 Lighthouse 모바일 점수가 Accessibility 95점 이상, Performance 90점 이상이다.
- SC7. JS를 끈 상태에서도 세 화면의 모든 기사·날짜 링크로 이동할 수 있다.
- SC8. 키보드만으로 홈 → 뉴스피드(카테고리 전환 포함) → 캘린더 → 날짜별 뉴스피드까지 이동할 수 있다.
- SC9. White·Dark 모드 모두에서 본문 텍스트 대비가 4.5:1 이상이다.
- SC10. `./gradlew test`가 통과하고, 변경 후 `workflow_dispatch` 1회 실행으로 새 화면이 GitHub Pages에 배포된다(수동 수정 0회).
- SC11. 쓴 21st.dev 컴포넌트의 출처와 라이선스가 문서에 모두 기록돼 있다.
- SC12. 처음 방문하면 기기 설정을 따른다(라이트 기기 → White, 다크 기기 → Dark). White나 Dark를 고르면 다른 페이지로 이동하거나 새로고침해도 유지되고, 다른 배경이 잠깐 보이는 깜빡임이 없다.
